# Linux SDR (V4L2)

Linux has its own interface for SDR receivers: receivers with a kernel
driver appear as `/dev/swradio0`, `/dev/swradio1`, … The input *Linux SDR
(V4L2)* uses them directly. No library (librtlsdr, libairspy) is needed.

Kernel drivers that provide such a device include:

| Driver | Receivers |
|---|---|
| `rtl2832_sdr` | DVB-T USB sticks with the Realtek RTL2832U (rtl-sdr) |
| `airspy` | Airspy R2, Airspy Mini |
| `hackrf` | HackRF One |
| `msi2500` | SDRplay RSP1 and Mirics MSi2500 sticks |

The input is only available on Linux.

!!! warning "RTL-SDR Blog V4"
    The Linux kernel doesn't support the RTL-SDR Blog V4 yet: it tunes
    to a wrong frequency (about 1.8 times the wanted one), so no DAB
    station is found. Use the [rtl-sdr](rtl_sdr.md) input for this stick.

## Choosing the device

In the receiver settings, disable *Auto detect* and choose *Linux SDR
(V4L2)* as input device. The *Linux SDR settings* list the receivers that
were found; *First found* uses the first one that can be opened.

With *Auto detect*, welle.io tries the Linux SDR devices last, after the
Airspy, rtl-sdr and SoapySDR inputs.

## Access to the device

The user needs read and write access to `/dev/swradioN`. Desktop
distributions usually grant it to the logged in user; otherwise add the
user to the group of the device (`ls -l /dev/swradio*`, often `video` or
`plugdev`).

A receiver can be used either by its kernel driver (this input) or by its
library (the rtl-sdr and Airspy inputs), not by both:

* Many distributions block the kernel driver of the rtl-sdr sticks when the
  rtl-sdr package is installed (`/etc/modprobe.d/rtl-sdr-blacklist.conf`,
  module `dvb_usb_rtl28xxu`). Then there is no `/dev/swradioN` for the
  stick.
* If the library takes over the receiver, `/dev/swradioN` disappears until
  the receiver is plugged in again.

Only one program can receive with a device at a time. If another program
uses it, welle.io shows "The Linux SDR device is used by another program."

## Gain

The gain controls depend on the driver:

* **airspy**: the tuner controls the LNA and mixer gain itself, the
  automatic RF gain and the gain slider set the IF gain (like the *Hybrid*
  gain mode of the [Airspy](airspy.md) input). There is no bias tee.
* **rtl2832_sdr** with the R820T/R828D tuner: the driver has no gain
  control, the tuner sets its gain itself. The gain slider has no effect.
* Other drivers: the IF gain, or the LNA gain if there is no IF gain.
